# Shine 预设代码分析与声明一致性审查 PRD

> **状态：** 实施中；阶段 A 契约与阶段 B 分析核心已落地，阶段 C–D 准入集成尚未完成。
> **日期：** 2026-10-22。
> **前置条件：** App 哈希规则复用、无新增临时信任时省略重复审查规划两项优化已完成。
> **定位：** 内置静态分析与声明一致性检查，不提供运行时权限隔离。
> 本文是内部产品计划，不定义已经发布的 CLI 或 JSON 接口。

## 1. 背景

Shine 当前能够推导自身结构化操作的权限，并通过源快照、状态观察、批准和锁内重检保护生命周期执行。
对于任意脚本，`shine.toml` 中的能力声明仍属于作者说明，系统尚不能独立检查声明是否遗漏了脚本中的可识别行为。

本项目补充这一能力：自动分析本次操作涉及的代码，与作者声明对照；匹配时静默通过，确定不匹配时要求修复，
无法判断的部分进入现有代码信任审查。声明一致性检查不证明脚本安全，也不限制运行中的脚本实际能访问哪些资源。

现行 [ADR 0091](kb/decisions/0091-derived-code-boundaries-and-author-capability-statements.md)
规定作者能力说明可选且不产生代码信任。本文提出的确定差异准入检查是未来行为变更，不能视为已经取代该 ADR。
实施时须明确记录新的契约、兼容边界及对现行决策的修订。

## 2. 产品目标

1. 自动发现受支持脚本中的文件、网络、命令和环境变量使用。
2. 将分析证据与 `shine.toml` 的显式声明结合，定位确定的遗漏或范围不匹配。
3. 对确定的不匹配暂停操作，要求补充声明或修改脚本。
4. 匹配时不增加分析输出或额外确认界面。
5. 对未知行为明确展示覆盖缺口，保留现有代码信任要求。
6. 分析结果绑定源码和分析规则，避免旧报告用于新代码。
7. 同一源码的分析结果在一次命令内复用，不随每次状态重新规划重复计算。

## 3. 非目标

首版不包含：

- 操作系统沙箱、系统调用拦截或运行时越权阻止。
- 执行脚本进行动态观测。
- 下载依赖、访问网络或执行外部分析命令。
- 根据分析结果自动授予代码信任、管理员权限或 Plan 批准。
- 自动扩大能力声明后继续执行。
- 完整跨语言、跨第三方依赖的程序分析。
- 基于 LLM 判断是否允许执行。
- 独立 `shine preset analyze` 命令或要求用户显式开启分析的 `--analyze-code` 选项。
- 整体 Planner 拆包或独立分析包发布。

## 4. 首版分析范围

优先支持 **Bun JavaScript／TypeScript 的 App 脚本**。

| 对象 | 首版处理 |
|---|---|
| generator、脚本 hook、artifact、teardown | 根据现有 Core 类型化入口识别 |
| 类别内可静态解析的相对依赖 | 递归分析，处理循环依赖 |
| 已支持的 Node／Bun 内置 API | 识别行为并生成证据 |
| 第三方包、远程模块、原生扩展 | 不下载、不执行，报告覆盖缺口 |
| 动态 import、动态 require、eval | 报告动态行为及未知范围 |
| 原生命令 hook、其他脚本语言 | 标记未覆盖，保留现有信任流程 |
| 与本次操作无关的代码入口 | 不纳入本次操作的一致性阻断 |

`preset lint` 检查类别中受支持的全部入口；真实操作及作者 Plan／fixture 依据各自输入，
只检查本次可能执行或交付的入口。作者工具的具体范围见第 12 节。
依赖解析遵循明确的有限规则，路径逃逸、别名不明确及缺失依赖必须有稳定诊断，不得猜测解析结果。

选中类别或文件不等于触发其中的脚本。Core 复用既有平台、操作、`when_env`、`auto`、
生命周期 hook 等明确触发条件确定入口集合：已确定不会执行的入口跳过分析，仍可能执行的入口保守纳入。
这不是脚本控制流可达性分析；不通过读取源码中的条件分支证明代码不会执行。
例如显式评估中 `when_env` 缺失而沿用静态回退、隐式升级跳过 `auto = false` 的 generator 时，
不因这些未触发脚本的解析错误或声明差异增加阻断。原操作要求输入存在而拒绝执行的情形仍按原规则失败，
不能把 refresh 的输入错误改成静态回退。缺少代码信任或批准也不能被解释成入口不会执行而跳过分析。
触发条件由 Core 使用已捕获的请求和输入判断；分析器不读取真实环境值。重新规划改变入口集合时，
必须重新校验分析范围和证据，不能用先前未触发的结论允许新增入口执行。

共享代码变更仍须沿用现有受影响目标集合，不能仅检查命令行显式选择的目标。
扩展到 Shell 交付时，安装阶段的分析不代表对未来每次命令调用进行运行时监控。
来源缺失后的 receipt 驱动卸载和恢复必须保留既有语义；不能为本次不执行的代码新增分析前提。

首版执行入口必须包含以下两类，不以是否生成生命周期 Plan 判断是否需要分析：

| 执行路径 | 分析入口与准入要求 |
|---|---|
| App install、upgrade、refresh、artifact apply/remove，以及可能触发脚本的卸载路径 | 按 Core 触发条件确定可能执行的 generator、脚本 hook、artifact 或 teardown，纳入现有 Plan 批准与执行校验 |
| `app info --run-generators`、定向及全局 `update --run-generators`，以及对应 Core／Frontend 显式评估入口 | 在选中项中按 Core 触发条件确定可能执行的 generator，即使不生成生命周期 Plan 也必须满足相同的一致性准入要求 |

普通 list/info/update 等不执行代码的检查保持只读，不因本功能隐式运行 generator。
Core 负责执行入口的完整性，不能仅在 CLI 命令分支中加检查。

## 5. 核心交互

需要生命周期批准的操作沿用以下流程：

```text
捕获有效 Preset 快照
    → 现有规划逻辑按触发条件确定本次可能执行的代码入口
    → 静态分析 + 作者声明一致性检查
        ├─ 阻断：展示确定差异或失败诊断，暂停
        └─ 允许继续：无诊断时静默，有非阻断诊断时按规则展示
    → 现有 Security Plan、代码信任及管理员授权流程
    → 锁内重新校验并执行
```

不新增独立的分析确认界面。匹配后无需展示审查界面，仅指不展示额外的分析界面；
现有 Security Plan 确认、外部代码信任与管理员授权仍按原规则执行。
静态配置复制等不涉及代码的操作，直接沿用现有流程。

显式 generator 评估使用相同分析器和一致性判断，但不新增生命周期 Plan 或批准步骤：

```text
捕获有效 Preset 快照 → 现有显式评估逻辑按触发条件确定可能执行的 generator
    → 分析并校验该入口的一致性证据 → 保留既有持久代码信任检查
    → 创建临时执行快照并运行 generator → 在内存中计算状态或差异
```

确定差异、分析失败或证据失效必须在对应脚本的临时执行快照落盘和进程启动前拒绝该次评估。
覆盖缺口在现有评估结果中明确展示，不新增确认界面，也不以一次操作同意代替现有持久信任要求。
保持逐文件处理：文件级检查或评估失败不跳过其余可独立处理的选中项，输出各项状态后以非零状态结束命令；
取消、命令总预算耗尽及无法安全继续的分析器故障则终止剩余工作，具体规则见第 11 节。
被准入阻断的文件不得执行 generator。评估仍不安装配置、不更新安装 receipt、不触发 hooks 或 artifacts；
获准执行所需的临时快照及其清理继续遵守既有规则。

## 6. 准入结论与诊断

声明表示作者承诺覆盖的能力范围，不要求声明集合与分析发现机械地逐项相等。

准入结论只有“允许继续”或“阻断”，由当前分析范围内是否存在阻断诊断决定。
“允许继续”仅表示本检查没有阻断原因，不授予执行权限，也不替代既有 Plan readiness、代码信任或批准。
生命周期操作将阻断原因并入现有 readiness／诊断；显式评估按文件应用，命令级终止规则优先。
不新增平行审批状态机、确认步骤或可授予的分析权限。
入口集合为空时沿用原流程，不运行源码分析，也不产生对未触发脚本的匹配结论。

| 情况 | 准入影响 | 诊断与展示 |
|---|---|---|
| 已识别行为均被声明覆盖，且无诊断 | 允许继续 | 静默；本文“匹配通过”仅指这一展示结果 |
| 明确发现行为，缺少对应声明 | 阻断 | 确定差异：补充声明或删除该行为 |
| 声明范围不足以覆盖可确定的行为 | 阻断 | 确定差异：修正范围或缩小脚本行为 |
| 声明存在，但分析未发现对应行为 | 本身不阻断 | 未印证声明：详细报告提示，不认定声明错误 |
| 动态目标、外部依赖、子程序效果或环境身份无法比较等导致无法判断 | 本身不阻断 | 覆盖缺口：在现有代码审查或显式评估结果中提示 |
| 受支持源码解析失败、分析器故障或资源预算耗尽 | 阻断 | 分析失败：按第 11 节处理文件级失败或命令级终止 |

确定差异、分析失败、覆盖缺口和未印证声明是可同时存在的诊断，不是互斥准入状态。
覆盖缺口和未印证声明本身不要求额外确认；无阻断诊断时允许进入既有授权流程，但不能因此声称完全匹配。
应分析的入口缺少有效证据时不能视为无诊断；按第 10、11 节重新获取证据或拒绝继续。

具体要求：

- 作者声明缺失不再对所有受支持行为天然可接受。
- 只有明确、可比较的发现才能触发缺少声明或不匹配阻断。
- 未识别的行为不能被解释为不存在。
- 分析发现表示代码存在相应行为的可能性，不保证运行时一定发生。
- 不得通过扫描字符串、注释或变量名称直接推断确定行为。
- 动态行为及外部依赖不得因作者补充说明而自动变成已验证。
- 已知子程序的命令声明匹配，只确认命令身份被覆盖；子程序效果未分析仍构成独立覆盖缺口。
- 同时存在确定差异和未知行为时，覆盖缺口不得覆盖确定差异的阻断，其他诊断也不得丢失。

代码信任不能绕过确定的一致性失败。`--yes`、持久 trust 和 Development trust
均不能消除阻断诊断或将阻断转换成允许继续。

## 7. 差异修复体验

确定不匹配时，输出至少包含：

- 逻辑目标和代码入口。
- 行为类别。
- 现有声明与发现之间的差异。
- 类别内文件及行列位置。
- 两种修复方向：补充准确声明，或修改脚本以符合声明。

禁止默认提供允许任意文件、网络或命令作为通用修复。
首版不自动修改 `shine.toml`。用户修改声明或脚本后，必须重新捕获、分析和审查，旧批准不能继续使用。

## 8. 初始分析规则

采用语法解析和有限的绑定识别，不以正则扫描作为主要分析方法。

| 类别 | 初始识别范围 | 处理原则 |
|---|---|---|
| 环境变量 | 支持形式的 `process.env`、`Bun.env` 访问 | 识别读取名称，不读取值；按入口环境契约比较，动态名称标记未知 |
| 文件访问 | 明确支持的 Node／Bun 文件读取、写入、删除 API | 区分操作类型；动态路径不猜测 |
| 网络访问 | 支持形式的 `fetch` 等调用 | 不请求目标；无法解析地址时标记未知 |
| 子进程 | 支持的 Bun／Node 进程启动 API | 区分已知程序和动态程序；命令身份比较与子程序效果未分析分别记录 |
| 动态代码 | eval、动态模块加载、可识别的 shell 执行 | 显式标注分析边界 |

每条规则必须定义支持语法、绑定与别名处理、变量遮蔽、参数解析范围和不支持情形。
比较使用既有声明语义；无法表达或准确比较的发现记录为覆盖缺口诊断，
不临时发明路径通配、网络范围或权限继承规则。

### 8.1 环境读取与声明身份

源码证据记录脚本读取的名称；一致性判断同时使用 Core 提供的该入口有效环境契约，
不能把读取名称直接当作 `[permissions].environment` 的源名称。

| 环境来源 | 比较规则 |
|---|---|
| Core 固定契约变量，如 `SHINE_APP_OVERLAY_DIR` | 按该入口实际提供的固定变量集合识别，不要求作者重复声明；不能仅按 `SHINE_` 前缀豁免 |
| 入口专属注入，如 `generator.env`、脚本 hook 的 `env`、`artifact.env` | 将读取的 target 通过有效 `source → target` 映射还原为源身份，再核对源声明；不能借用同类别其他入口的映射 |
| 未被固定契约或有效注入映射解释的名称 | 记录环境来源无法比较的覆盖缺口；不假定变量存在或不存在，不读取宿主环境，不以补充同名声明自动消除缺口 |

例如 `W_GET_CLOUD_SURGE_SUBSCRIPTION_URL=SURGE_SUBSCRIPTION_URL` 注入后，
脚本读取 `SURGE_SUBSCRIPTION_URL` 应核对源 `W_GET_CLOUD_SURGE_SUBSCRIPTION_URL` 的声明。
`plain/secret` 身份来自既有声明及 Core 环境输入契约，不根据变量名称、源码或真实值猜测；
无法确定时报告无法比较，既有注入与敏感性校验仍独立执行。固定变量覆盖映射等优先级沿用执行器语义。

分析本身不创建注入项、不扩大环境白名单，也不改变现有输入缺失或敏感性错误的处理。
没有发现源码读取不能取消既有注入要求；环境写入或删除不能被当成读取并据此要求注入。

### 8.2 子进程覆盖边界

每个受支持的子进程调用分别记录命令身份发现和“子程序效果未分析”的覆盖缺口。
已知程序可以参与命令声明比较，动态程序还需记录命令身份未知；两者都不能推断子程序的
文件、网络、环境或后续进程效果。首版不递归执行或分析子程序，也不因程序常见、声明齐全或已有 trust 而消除该缺口。

例如 `Bun.spawn(["curl", …])` 在 `commands` 包含 `curl` 时仅命令身份匹配，整体仍是覆盖不完整；
补充文件或网络声明也不能将这些未经分析的效果变成已验证。若同时缺少 `curl` 命令声明，
仍以需要修复阻断，并保留子程序覆盖缺口，不能用未知效果掩盖确定差异。

## 9. 架构设计

首版在 `shine-core` 内建立独立分析模块，暂不拆包。

```text
Preset 快照 + 类型化入口
    → 静态分析器
    → 行为证据报告
    → 声明一致性判断 ← 已解析的作者声明 + 入口有效环境契约
    → Core 准入结论 + 可并存的诊断
    → CLI 展示 / 现有批准流程
```

| 模块 | 职责 |
|---|---|
| 现有 Preset 解析及 Core 环境契约 | 解析声明、确定有效源码和入口，提供有效注入映射及固定变量身份，不提供环境值 |
| 静态分析器 | 解析源码，产生行为证据和覆盖缺口 |
| 一致性判断 | 比较证据与声明，以阻断诊断决定是否允许继续，保留覆盖缺口及未印证声明 |
| Planner／Frontend、显式评估及作者工具编排 | 复用同一准入判断，分别纳入生命周期批准、无 Plan 的评估或假设性作者报告 |
| CLI | 静默通过、展示差异和覆盖缺口 |
| 执行器 | 保留现有所有权、权限、锁和现场状态校验 |

分析器不依赖 CLI，不拥有进程、网络、写入、提权或批准能力。
入口发现与 Preset 语义由 Core 现有模块负责，不在分析器中复制 TOML 或领域解析。
分析结果是证据；作者声明和分析发现都不能自动转化成额外执行权限。

## 10. 报告与批准绑定

由于一致性结果能够阻断操作，本版不采用纯附加报告、完全不影响批准契约的设计。

内部报告至少包含：

- 报告 schema、分析器版本和规则集版本。
- 有效源码摘要、入口集合、分析配置及声明身份。
- 每个入口的有效环境契约身份，包括注入映射、源敏感性及固定变量规则，不包含环境值。
- 准入结论及可并存的诊断，不另设匹配、关注、未知等互斥准入状态。
- 行为发现、稳定诊断代码和源码位置。
- 已覆盖范围、未知边界和失败原因。

批准绑定必须覆盖所有影响准入判断的身份，包括源码、声明、入口有效环境契约、一致性策略及分析规则版本。

1. Core 验证证据与当前输入一致，不能接受前端上传的任意报告作为准入依据。
2. 存在阻断诊断或应分析入口缺少有效证据时，操作不可批准。
3. 覆盖不完整保留既有未隔离代码边界与信任要求。
4. 源、声明、入口有效环境契约或影响准入的策略变化，使旧一致性证据和对应批准失效。
5. Plan 只保留必要的摘要、身份和诊断，不嵌入完整源码或庞大分析报告。
6. 版本化方案在契约阶段确定，并遵守现有批准及报告兼容规则。

无 Plan 的显式评估同样由 Core 核验证据与本次捕获的源码、按触发条件确定的入口和有效环境契约一致，
并在执行前落实准入；没有生命周期批准对象不能成为绕过理由。证据不能作为代码信任凭据，
也不能让只读前端获得显式评估或进程执行能力。

## 11. 复用与执行时机

分析不应嵌入每个 `plan_*` 调用。

- 审查、显式评估及作者工具编排层按各自范围、有效源码和入口集合请求分析。
- 相同源码分析输入在当前命令内复用；源码事实与按入口计算的一致性结果分别管理。
- 同一脚本被不同入口复用时，可复用源码事实，但须按各入口的有效映射、源敏感性、固定变量规则及声明分别比较和绑定。映射变化可重做比较，不能沿用其他入口的一致性结果。
- 临时代码信任变化不会改变源码分析事实，可重新做准入装配而不重解析源码。
- 状态重新规划继续读取真实资源，不复用旧文件观察。
- 执行时核验分析证据身份，不在持有生命周期锁期间重新运行完整分析。
- 证据缺失或过期时拒绝沿用，在锁外重新分析并按原路径重新审查；显式评估不因此新增批准步骤。
- 首版不提供持久磁盘缓存。

需要明确限制单文件大小、依赖图大小与深度，以及命令内的累计字节数、文件数量、发现数量和分析工作预算。
具体阈值通过真实预设样本与压力测试确定；命令级累计预算不得在切换文件或入口时重置。

| 失败作用域 | 处理规则 |
|---|---|
| 入口一致性级：缺少声明或声明范围不足等确定差异 | 仅阻断该入口及其有效环境契约、声明对应的一致性结果；其他入口即使复用同一源码，也须分别比较，不能继承这一阻断 |
| 源码或依赖图级：局部解析错误、局部大小／深度超限等可隔离问题 | 阻断依赖该失败源码或依赖图分析结果的入口；不影响无需该结果的其他入口 |
| 命令级：用户取消、命令总预算耗尽、无法安全继续的分析器故障 | 立即停止调度剩余分析和新的脚本进程；按现有取消及清理机制收尾，不把它降为普通文件错误后继续 |

入口一致性级及源码／依赖图级阻断发生后，显式评估和 lint 可继续处理其他未受影响的项，最后报告失败；
fixture 批次继续按预期断言判定各用例。同一生命周期 Plan 仍按整个已审查操作的 readiness 决定是否执行，
不能因为其他入口单独允许继续而将该 Plan 改为部分批准。

取消按现有命令取消语义退出，总预算耗尽或分析器故障以失败退出；均不能输出本次整体成功或可继续执行的结论。
能够正常收尾并返回报告时，已完成的逐项结果可保留，未完成或未处理项须标为未完成，不能伪装成匹配、无发现或不存在。
能够正常收尾的取消路径沿用现有进程停止及临时执行快照清理机制，清理失败按原规则报告，不承诺无条件清理成功。
任务被直接取消、进程被强制终止等无法正常收尾的情形，保留 [ADR 0092](kb/decisions/0092-app-execution-snapshots.md)
的边界：可能留下 invocation 目录，后续操作不得将其复用为可执行输入；不要求此时还能返回完整报告。
本功能不新增取消安全的快照清理框架、自动回收或恢复机制，也不新增回滚先前已完成操作的事务。
取消／失败处理属于编排控制，不增加第三种准入状态，也不赋予分析器进程控制或写入能力。

## 12. 作者工具集成

复用现有作者工具，不增加独立 analyze 命令，也不复制分析器或准入规则。

| 工具 | 范围与结果 |
|---|---|
| `preset lint` | 按支持的平台和元数据检查类别内全部受支持入口；不以当前机器缺少 `when_env` 等运行输入跳过。确定差异和分析失败作为错误，覆盖缺口和未印证声明按分类展示 |
| `preset plan` | 在现有假设性请求和模拟输入下，使用 Core 触发条件确定可能执行的入口，复用分析与准入判断；阻断诊断参与 `ready`，非阻断诊断不单独使其为 false |
| `preset test` | 每个 fixture 使用声明的模拟平台、输入和状态，通过同一作者 Plan 路径检查；可断言 readiness 及稳定分析诊断，避免独立实现一套分析判定。正确预期阻断的负向用例可以通过，命令级终止不能作为预期阻断消化 |

同一源码、入口、有效环境契约和规则下，作者工具与运行时对确定差异及分析失败的判断必须一致。
lint 的全入口检查与 Plan／fixture 的触发范围可以不同；报告应说明实际范围，不能把模拟输入未触发解释成脚本已匹配。
模拟输入缺失时沿用现有假设，不读取宿主环境或秘密；测试需要触发 generator 时使用现有 fixture 输入表示。
既有 ownership、输入缺失和 trust 等其他原因仍可能使作者 Plan 不 ready，不能用分析允许继续覆盖它们。

作者 Plan／fixture 保持只读、假设性和不可执行，不创建批准、运行代码、落盘执行快照、初始化运行时状态或记录信任。
其报告中的新增分析内容只投影安全诊断和必要的范围摘要，不导出可供执行接收的证据或批准身份。
保留原有配置合法性验证，不用源码分析替代 schema 校验；源码差异通过诊断和 readiness 表达，不冒充 TOML 语法错误。
lint 的 `--deny-warnings` 仍是独立的作者 CI 退出策略，不改变运行时准入，也不把覆盖缺口变成权限要求。
各工具退出码及 JSON／fixture 报告变化须明确版本化并记录兼容影响；命令级终止统一遵守第 11 节。

`preset validate` 不直接演变成脚本效果分析器。
作者工具继续在普通配置初始化之前路由，不创建运行时状态或信任记录。

## 13. 隐私与展示

- 默认不输出源码片段、原始 argv、环境值、带凭据的 URL 或原始解析器错误。
- 使用类别内逻辑路径和源码位置，不暴露机器私有路径。
- 行为目标只有在可以安全结构化时才展示，否则使用类别和不透明身份。
- 文本输出编码控制字符。
- 规范报告保持确定性，不混入耗时、随机 ID 或机器位置。
- 摘要用于绑定，不承诺隐藏低熵敏感信息。
- 不出现安全通过、无越权风险、已验证全部权限等结论。

匹配通过时不增加常规输出；详细模式可以展示分析范围和结果摘要。
所有完成或匹配结论仅针对声明的分析范围，不表示穷尽脚本效果。

## 14. 验收标准

必须覆盖以下独立场景：

1. 声明与发现匹配时，无额外分析确认或常规输出。
2. 缺少明确声明时，在预设执行及资源修改前暂停。
3. 声明范围不足时，提供可定位的差异。
4. 修改声明或脚本后，旧证据与旧批准不可复用。
5. 信任授权及 `--yes` 不绕过确定的不匹配。
6. 动态或外部依赖不会被错误标记为完全匹配。
7. 分析失败、超限与不支持能够区分，不伪装成无发现。
8. 分析不执行进程、不访问网络、不读取真实环境值。
9. 多次状态重新规划不会重复分析同一源码。
10. 只读能力、批准消费、锁内重检和恢复行为保持成立。
11. 非代码操作不增加分析负担，来源缺失的 receipt 驱动清理不要求重建脚本。
12. 不同平台的逻辑路径、源码位置和规范报告保持一致。
13. 默认输出不泄露敏感源码、字面量或错误内容。
14. 共享资源影响的目标不会被选择器范围遗漏。
15. 未知行为与确定差异并存时，确定差异仍然阻断。
16. 按 Core 触发条件纳入本次分析的脚本存在确定差异时，生命周期执行与 `app info --run-generators`、定向及全局 `update --run-generators` 均不能执行它；直接 Core／Frontend 显式评估调用也不能绕过。差异、分析失败或证据失效均在该脚本的执行快照落盘及进程启动前被拒绝。
17. 显式评估不新增生命周期批准或一次操作信任。文件级失败后其余独立选中项继续处理，最终非零退出；覆盖缺口可见，普通检查仍不执行代码，评估不安装配置、更新 receipt 或触发 hooks/artifacts，临时快照按原规则清理；命令级终止适用第 26 项。
18. 环境映射 `SOURCE=TARGET` 下读取 `TARGET` 核对 `SOURCE` 的声明与敏感性，不误要求声明 `TARGET`；缺失源声明仍被识别，不能用同类别其他入口的声明映射替代本入口映射。
19. Core 固定变量无需重复声明；伪造 `SHINE_` 前缀、未映射的宿主变量和动态名称不能获得该豁免。未知环境身份保持覆盖不完整，不读取真实值、不猜测 `plain/secret`，写入或删除不被误判为注入读取。
20. 两个入口共享同一脚本但使用不同环境映射或源敏感性时，源码分析只做一次，一致性分别计算；验证一个入口存在声明差异而另一个声明完整时，前者阻断、后者仍可单独允许继续，显式评估不因共享源码跳过后者。共享源码或依赖的解析失败则阻断所有依赖该失败结果的入口，其他独立入口不受影响。同一生命周期 Plan 仍整体遵守 readiness，不产生部分批准。仅修改映射、源敏感性或固定变量规则也使旧一致性证据及对应批准失效，无 Plan 的评估同样拒绝失效证据。
21. 已知程序且命令声明匹配时，命令发现可标记匹配，但子程序效果未分析使整体保持覆盖不完整；新增文件或网络声明、持久 trust 或 `--yes` 均不消除缺口。缺少命令声明时仍阻断，动态程序同时保留身份与效果未知。
22. 显式评估因 `when_env` 缺失沿用静态回退、隐式升级跳过 `auto = false` generator，以及其他明确不触发脚本的操作，不解析这些未触发脚本，也不因其解析错误或声明差异增加阻断。refresh 等原有输入错误仍按原规则失败。
23. 条件尚不能排除执行的入口保守纳入，缺少 trust／批准不构成跳过理由。相同源码下重新规划使入口从未触发变为可能执行时，必须获取相应证据并重新审查；旧批准不能覆盖新增入口。
24. 相同分析输入下，lint、作者 Plan、fixture 和运行时对确定差异及分析失败给出一致诊断；作者 Plan 的 `ready` 及 fixture 断言反映阻断。正确预期 `ready = false` 和对应诊断的负向 fixture 可以通过，命令级终止不能被断言转为成功。覆盖缺口本身不使 ready 为 false，其他既有 blocker 仍有效。
25. lint 能检查模拟／当前运行输入未触发的入口；作者 Plan／fixture 明确显示其假设下的实际范围，不把跳过标成匹配。触发与未触发 fixture 均不读取真实环境、不执行进程、不创建执行快照、运行时状态、信任或批准；报告不能被执行接口当作证据接收。
26. 用户取消、命令总预算耗尽或无法安全继续的分析器故障后，不再调度分析或启动新的 generator，未处理项不报成功。分别覆盖能够正常收尾的取消和无法正常收尾的任务取消／进程终止：前者按现有机制停止在途工作、尝试清理临时快照，清理失败沿用原有错误处理策略；返回报告时保留已完成结果并标明未完成项；后者允许 invocation 目录残留，不要求返回完整报告，但后续操作不得复用残留目录作为可执行输入。不以所有取消方式均无残留作为验收条件，也不引入自动回收或恢复机制。使用多个单独未超限、累计超限的入口验证预算不会按入口重置；局部失败仍允许未受影响的入口继续。
27. 仅有覆盖缺口、仅有未印证声明及二者并存时，本检查均允许继续且不新增确认；出现确定差异或分析失败则阻断，全部诊断可并存。无诊断才静默匹配；仍需通过原有 trust／Plan 批准。lint 的 `--deny-warnings` 可以影响 CI 退出码，但不能改变运行时准入。

测试按能力边界、规则准确性、依赖解析、报告隐私和审查集成分别组织。
保留既有陈旧批准、锁等待和恢复测试，不用分析测试替换它们。

## 15. 实施阶段

| 阶段 | 交付 | 验收门槛 |
|---|---|---|
| A：契约与规则 | 二值准入与诊断、入口触发条件、环境比较语义、批准与评估证据绑定、解析器评估 | 明确覆盖缺口、文件级失败与命令级终止边界 |
| B：分析核心 | App Bun 入口、本地依赖及初始规则 | 只读、确定性、覆盖缺口与隐私测试通过 |
| C：作者工具 | 集成 `preset lint/plan/test`，复用模拟输入和分析判断 | 同范围下准入诊断一致，readiness 与 fixture 断言有效，保持只读与假设性 |
| D：内置审查与显式评估 | 自动检查、静默通过、差异阻断、按入口比较及证据复用 | 全部执行入口受检；不绕过现有批准与持久信任，陈旧证据不能执行 |
| E：范围扩展 | 评估其他入口、语言及独立包 | 根据真实覆盖率、误报和维护成本决定 |

解析器选型需核查 Rust 版本兼容性、许可证、语法覆盖、资源限制和错误位置能力。
不得依赖执行预设或下载依赖来完成分析。

首批规则应以人工标注样本验证；除简单规则示例外，还需覆盖仓库真实预设、别名、遮蔽、
动态参数、依赖缺失和恶意构造输入。记录规则级误报与覆盖缺口，不以单一覆盖率声称代码安全。

核心模块接口稳定且出现独立依赖或第二个消费者后，再评估提取 `shine-analysis`。
包拆分不是首版完成条件，也不应为追求目录结构提前增加公共接口。

## 16. 兼容性与文档

这是一项行为变化：以前可以执行的受支持脚本，可能因声明缺失而需要修复。

发布前应：

- 检查并补全内置预设的确定缺口。
- 提供外部预设迁移说明，不自动扩大声明。
- 明确首版语言与规则覆盖范围。
- 按仓库版本约定评估 CLI、报告和批准契约的兼容变化。
- 同步更新英文与简体中文手册、作者 skill、架构 KB 和相关 ADR。
- 不将内部 PRD 或内部操作流程发布到公共站点。

本 PRD 写入本身不修改现行契约或公共手册。上述实现与迁移义务在各阶段落地时完成。

首版完成标准：分析自动发生，匹配静默通过，确定差异必须修复，未知范围清楚可见；
现有安全授权仍独立成立。
