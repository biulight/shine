# Env 配置分层与可预测写入 PRD

> **状态：已实现；Windows 实机验证与旧版降级演练通过，待 breaking release 发布。** 日期：2026-10-11。
> 本文采用 breaking change 方案，定义统一的新行为与人工升级要求；命令选项尚未发布。
> 实现与双语手册、KB、ADR 0109 和 CHANGELOG 同步更新；本次不修改版本或发布。

## 1. 背景与问题

Shine 使用同一套有效 env 值支持预设模板、显式环境注入和 secrets 操作。
目前配置同时存在于全局、项目和 overlay 中，读取结果与写入目的地不容易预测。

| 问题 | 当前行为 | 用户影响 |
| --- | --- | --- |
| 默认值持久化 | 加载时把缺失的内置变量补入全局 `[env]` 并保存 | 无法区分用户意图与自动默认值；默认值可能长期固定在旧版本 |
| 优先级 | 所有独立覆盖文件高于全局和项目 `[env]`；overlay 高于全局覆盖文件 | 项目设置可能不生效；本机设置可能被同步值覆盖 |
| 写入目标 | 默认修改当前配置；发生覆盖时拒绝，`--force` 改写有效值来源 | 同一命令因键的来源不同而修改不同文件，可能写入可丢弃镜像 |
| 来源展示 | 全局与项目 `[env]` 都显示为 `config.toml` | 无法准确定位有效值，也无法看到被覆盖的定义 |
| 升级影响 | 旧文件没有足够的逐键用户意图信息 | 不能安全自动清理默认值；改变排序可能改变有效值 |

### 1.1 历史设计意图

[2026-07-15 的经验记录](kb/lessons.md#2026-07-15--env-setencrypt-silently-wrote-a-value-an-override-file-kept-shadowing)
明确记录：overlay 高优先级用于让维护端同步的值覆盖消费端陈旧的 `config.toml` 值。
[ADR 0010](kb/decisions/0010-git-managed-overlay.md) 定义 Git 托管 overlay 为可丢弃的强制镜像。
因此当前行为有明确用途，不能当作无意的排序错误直接修复。

本文建议改变默认产品定位：overlay 提供可同步的配置基线，用户显式的本机及项目配置可以覆盖它。
新旧安装统一使用新顺序，不保留“维护端值始终优先”的兼容模式。
这是有意的不兼容变更，依赖旧顺序的用户须按第 8 节人工调整配置。

### 1.2 当前实现依据

- [配置加载](../cli/src/config/load.rs)：先合并全局、项目 TOML，再应用全局、overlay、项目 env 文件。
- [env 分层](../cli/src/config/env_layer.rs)：`ensure_env_defaults` 补值并保存；覆盖来源按键记录。
- [配置保存](../cli/src/config/save.rs)：项目稀疏保存、注释保留与私有原子写入。
- [env 命令](../cli/src/env/commands.rs)：来源分组、覆盖检查及 `--force` 写入重定向。
- [env 值查找](../cli/src/env/mod.rs)：显式注入优先查找 `KEY_SECRET`，再查找 `KEY`。
- [当前配置手册](manual/reference/configuration.md)、[环境管理指南](manual/guides/environment.md)。

## 2. 目标与非目标

### 2.1 目标

1. 配置文件只记录显式配置，内置默认值在运行时兜底。
2. 默认遵循“配置基线 < 本机配置 < 项目配置”，同一范围内独立 env 文件覆盖 `[env]`。
3. 写入目标由用户选择或明确的默认范围决定，不由读取来源决定。
4. 用户能定位每个有效值及其覆盖链，敏感内容默认不展示。
5. 保留历史文件中的显式项，明确升级影响与人工调整路径，不猜测旧值的生成来源。
6. 区分“已保存到指定层”和“当前有效值已改变”，禁止误报生效。

### 2.2 非目标

- 不删除 `[env]` 或 `shine.env.toml`，不新增第三种 env 数据文件。
- 不改变配置根、预设根、项目向上发现及 overlay 文件合并规则。
- 不引入强制团队策略、项目继承屏蔽标记或进入目录自动导出环境变量。
- 不统一模板安装时渲染与运行时读取的行为，不自动执行 `shine upgrade`。
- 不改变 workspace source 顺序、子进程注入规则、`KEY_SECRET` 优先查找、加密格式或信任模型。
- 不读取和展示子进程的完整有效环境；本 PRD 的来源链限于 Shine 配置层。
- 不增加双读取策略、策略字段、新旧安装推断或自动配置迁移。
- 不增加默认值自动清理、批量项目迁移、迁移日志、专用备份及恢复系统。

## 3. 概念与范围

| 概念 | 定义 |
| --- | --- |
| 全局配置 | 当前 runtime root 下的 `config.toml`，通常为 `~/.shine/config.toml` |
| 项目配置 | 从调用目录向上找到的最近 `shine.config.toml`；无需 Git 仓库或外部预设目录 |
| 项目根 | 该 `shine.config.toml` 所在目录；项目 env 文件仅从这里读取 |
| overlay | 当前激活的手动目录或 Git 托管镜像 |
| 显式值 | 用户文件中实际存在的键，即使值等于内置默认值也属于显式配置 |
| 有效值 | 按第 5 节统一顺序合并后供 Shine 使用的值 |
| 写入范围 | 全局、项目、overlay，与某键的有效来源相互独立 |

`SHINE_CONFIG_DIR` 继续选择全局 runtime root。本文的 `~/.shine/` 只是默认路径示例，
实现不得硬编码。仅存在 `shine.env.toml` 不构成项目，也不新增跨祖先的多个项目层级合并。

## 4. 默认值与持久化

### 4.1 目标行为

- 内置默认值只在有效配置计算时参与合并，不因正常加载而写入 `[env]`。
- `env list/get/explain` 不为补默认值创建或重写配置文件；无需配置也能查看内置值。
- 首次需要可变 runtime 状态时仍可初始化配置，但不得把所有内置 env 默认值展开写入。
- 任何其他配置保存入口也不得把有效 env 表整体持久化。
- 保存某层时只更新该层的显式键，保留无关字段、注释、详细值描述和原有显式项。
- 用户主动把值设成内置默认值，必须生成显式项；不能因为有效值未变而省略该操作。
- 删除显式项后恢复继承；若最后只有内置默认值，则默认值仍生效，但不重新落盘。

运行时应分别保留原始层、有效值、来源和待写变更。不能只持有合并后的 map，
也不能仅依赖有效值前后差异推断用户是否要求保存一个显式项。

### 4.2 默认值更新

新版默认值只影响没有显式定义的键。历史文件中已有的值全部按显式值处理，
包括以前可能由 Shine 自动写入、或与旧默认值相同的项；只有用户主动删除后才恢复继承。
升级、加载及其他配置保存均不得自动清理这些项，也不维护历史默认值识别表。

## 5. Env 读取优先级

### 5.1 统一顺序

以下从低到高，后者覆盖前者：

| 顺序 | 层 | 文件位置 |
| --- | --- | --- |
| 1 | 内置默认值 | 二进制中的默认 env 定义 |
| 2 | overlay 基线 | `<active-overlay>/shine.env.toml` |
| 3 | 全局 `[env]` | `<runtime-root>/config.toml` |
| 4 | 全局 env 覆盖 | `<runtime-root>/shine.env.toml` |
| 5 | 项目 `[env]` | `<project-root>/shine.config.toml` |
| 6 | 项目 env 覆盖 | `<project-root>/shine.env.toml` |

此顺序中 overlay 与全局两层的完整结果，构成项目继承的基线。
所有安装统一采用此顺序，不根据文件是否存在、当前目录或安装历史选择算法。
各层使用同一个确定性解析器；不得因 `env get`、模板或运行入口不同而更换排序。
所有已选中的文件都须校验，不能因为某项会被覆盖就忽略错误格式。

字符串与仅含 `value` 的详细项都只覆盖值，并继承下层描述；
详细项显式提供 `description` 时才替换描述，空字符串表示清空描述。
配置层均没有描述时，继续使用预设 catalog 的描述兜底；显式空描述不再触发该兜底。
来源模型应分别追踪值和描述，避免把下层继承的描述误标为有效值所在文件提供。
不引入策略配置字段，也不为此保留 env 变量名称；env 文件中的同名普通键仍按 env 数据处理。

### 5.2 场景示例

假设 overlay 设置 `HTTP_PROXY_PORT=6152`，全局 env 文件设置为 `7890`，项目 `[env]` 设置为 `8080`：

- 升级后：项目内为 `8080`，项目外为 `7890`。
- 升级前：项目内外均为 `6152`，除非项目 env 文件另有定义。
- 升级后删除项目 `[env]` 的显式项，恢复为 `7890`。

配置变化仍按各消费者现有的生效时机处理。安装时渲染的内容需要既有 lifecycle 更新；
运行时读取入口使用下次加载结果。修改配置本身不批准执行预设或改写已安装产物。

## 6. 写入目标与命令行为

### 6.1 拟议接口

`env set`、`env delete` 和 `env secret encrypt --set` 共用以下目标规则：

| 参数 | 范围 | 默认文件 |
| --- | --- | --- |
| 不传范围 | 活动项目存在时为项目，否则为全局 | 对应配置文件的 `[env]` |
| `--global` | 全局，允许在项目中指定 | 全局 `config.toml` 的 `[env]` |
| `--project` | 当前项目；无项目则报错，不自动创建项目 | 项目 `shine.config.toml` 的 `[env]` |
| `--overlay` | 当前手动 overlay；托管镜像或无 overlay 则报错 | overlay 的 `shine.env.toml` |
| `--env-file` | 与默认范围、`--global` 或 `--project` 组合 | 对应范围的 `shine.env.toml` |

三个范围参数互斥。`--overlay --env-file` 可接受，目标仍是 overlay 的 env 文件。
只要传入任一范围参数或 `--env-file`，即为显式选择目标；
单独 `--env-file` 表示当前默认范围的 env 文件，仍需按 cwd 解析该范围。
脚本应同时写明范围和文件选项，避免依赖执行目录。
本期不提供任意文件路径写入或按有效来源自动写入。

示例均为拟议命令：

```bash
shine env set HTTP_PROXY_PORT 7890 --global
shine env set HTTP_PROXY_PORT 8080 --project
shine env set HTTP_PROXY_PORT 8081 --project --env-file
shine env delete HTTP_PROXY_PORT --global --env-file
shine env set HTTP_PROXY_PORT 6152 --overlay
shine env secret encrypt --from MY_TOKEN --set MY_TOKEN_SECRET --project --env-file
```

### 6.2 写入前预检

1. 解析明确的目标层与文件，校验格式及目标可写性。
2. 目标为 Git 托管镜像时始终拒绝，指引修改上游、使用手动维护目录或本地覆盖。
3. 检查是否存在定义同一存储键的更高优先级层，包括值恰好相同的情况。
4. 未传目标选项且被遮蔽时拒绝；展示目标文件、胜出来源及准确的替代命令，不创建文件。
5. 显式选择目标时允许维护被遮蔽的项，只修改目标文件，不自动移动或删除其他层定义。
6. 校验通过后按第 6.4 节提交；输出实际保存位置及提交后读取到的有效来源。

例如，在项目覆盖 `KEY` 时，`set KEY value --global` 仍可维护全局值，
输出“已保存到全局配置；当前项目仍由项目配置覆盖”。`--overlay` 同样可维护被本机覆盖的共享基线。
成功退出状态表示指定文件已保存；是否成为当前有效来源必须单独报告。
默认操作仍阻止无意的无效写入，显式操作不把“保存成功”描述成“当前生效”。
这替代历史经验记录中一律拒绝被遮蔽写入的规则，实现时须同步记录新的行为边界。

已有值相同也要保证显式项已保存。输出说明当前值是否改变，以及是否仍需通过既有 lifecycle 更新安装产物。
提交后重新读取失败时，报告“文件已保存，但有效状态核对失败”并返回失败，不能假称没有写入。

这三个写入入口的 `--force` 在 breaking release 中停止支持；
若保留旧参数解析用于诊断，必须拒绝请求且零写入，给出指向原目标层的准确替代命令。
不得重新赋予它绕过检查或重定向写入的语义。其他命令的同名选项不受影响。

对于 encrypt，写入预检在加密执行之前完成；被拒绝的目标不得引发无必要的加密工具调用。
预检检查的是目标存储键，例如 `MY_TOKEN_SECRET`。其他入口仍按现有 encrypted-first 规则
解析逻辑变量；若设置 `MY_TOKEN` 时已有有效 `MY_TOKEN_SECRET`，输出须提示显式注入仍优先使用密文键。

### 6.3 删除

- 仅删除目标文件实际存在的定义；不存在则报错，不向其他层继续查找或删除。
- 删除不会创建 tombstone，也不代表禁用继承值；空字符串仍是合法值。
- 显式选择目标时允许清理被遮蔽的旧项；删除后准确报告有效来源未变、恢复继承或已无配置值。
- 未指定目标时仍执行遮蔽保护；敏感值保持隐藏，不用删除操作隐式调整其他层。
- 不允许通过一次 delete 同时删除 `KEY` 与 `KEY_SECRET`。

### 6.4 并发变更与提交

预检记录目标原始内容、存在状态，以及决定目标选择和有效来源的配置输入。
对于 encrypt，还需记录 `--from` 等实际使用的来源；先预检再加密，避免持锁等待加密工具或人工输入。
最终提交前重新校验这些输入；变化时拒绝本次写入并要求重试，不自动覆盖或重新加密。

Shine 自身对同一目标的写入须串行化最终的重新读取、校验和原子替换，
相关配置保存入口遵循同一协调规则，避免两个进程同时通过旧快照检查后丢失更新。
只修改选定键，保留无关内容和描述；失败不得预先删除原文件。

该检查不宣称跨多个文件事务性锁定外部编辑器或 Git 操作；
原子替换防止文件损坏，提交前检查拒绝已观察到的变更，提交后重读报告当时的有效状态。
若高层文件在提交后再次变化，后续读取使用其新内容，不自动回滚已明确保存的目标项。

## 7. 来源展示

### 7.1 `env list`

- 分别展示 `builtin`、`overlay`、`global config`、`global env file`、`project config`、`project env file`。
- 文件层展示真实来源路径，项目来源不得再笼统标为 `config.toml`。
- 展示当前项目根；没有项目时明确表示当前使用全局范围。
- 保持当前值隐藏和终端宽度适配；源文件中存在不等于其值获胜。

### 7.2 拟议 `env explain KEY`

按统一顺序从低到高展示该键各层是否定义、哪层胜出及哪些层被遮蔽，默认不展示任何值。
`--reveal` 才展示值；不自动解密、不执行预设、不同步 overlay、不写配置。
输出包含值来源、描述来源和默认写入目标；路径仅供本地终端诊断，不进入安全报告或公共遥测。

```text
Key: HTTP_PROXY_PORT
  builtin                              shadowed
  overlay       <overlay>/shine.env.toml  shadowed
  global config <runtime>/config.toml     absent
  global env    <runtime>/shine.env.toml  shadowed
  project config <project>/shine.config.toml effective
  project env   <project>/shine.env.toml  absent
Default write target: project config
```

`env explain KEY` 展示存储键本身。若有效 `KEY_SECRET` 存在，应额外说明显式注入会优先使用它，
并指引查看其来源；不得让用户误以为 plaintext KEY 是实际注入值。
`env get` 保持现有单值输出，避免破坏脚本。

## 8. Breaking change 与人工升级指南

### 8.1 兼容矩阵

| 方面 | 升级后的行为 | 用户需要处理的事项 |
| --- | --- | --- |
| 配置格式与显式项 | 保留既有文件名、字符串和详细项格式，不自动重写 env 项 | 无需格式转换，历史自动补写项也按显式项处理 |
| 读取顺序 | 所有安装立即采用第 5 节顺序，不提供旧模式 | 核对曾同时在多个层定义的关键变量 |
| 内置默认值 | 只运行时兜底，不再自动补写 | 若要继承，主动删除历史同名项 |
| 无目标选项的写入 | 仍按 cwd 选择全局/项目配置，并保留遮蔽保护 | 失败时按提示明确选择目标 |
| 显式目标写入 | 可维护被遮蔽的项，成功表示保存到指定文件 | 检查输出中的有效来源，不把保存等同当前生效 |
| 旧 `--force` 写入 | set/delete/encrypt 的重定向语义停止支持，请求失败且零写入 | 更新脚本为准确的范围和文件选项 |
| Git 托管镜像 | 禁止 env 命令直接写入 | 修改上游或选择本地覆盖层 |
| 单值读取与注入 | `env get` 输出格式和 encrypted-first 查找保持 | 值仍可能因层顺序变化而不同 |
| 已安装产物 | 不因升级自动重渲染或执行预设 | 使用既有 update/upgrade 流程审查并更新 |
| 回退 | 旧二进制恢复旧排序，但不会恢复手工删除的项或已更新产物 | 按需恢复人工备份，重新审查产物更新 |

不新增 env 专用 `state migrate` 流程，不改变现有其他迁移功能。
不增加策略字段、新旧安装检测、批量项目参数、自动默认值清理或多文件迁移事务。

### 8.2 升级前准备

1. 记录使用中的 runtime root 与关键项目，不将 `~/.shine/` 假定为所有安装的根。
2. 对准备手动修改的全局、项目和手动 overlay 配置做私有备份；记录当前关键变量的有效来源。
   含秘密的文件不得提交仓库，读取值时避免将其复制到公共日志。
3. 更新使用旧 `--force` 的脚本。原目标为全局 env 文件时使用 `--global --env-file`，
   项目 env 文件使用 `--project --env-file`，手动 overlay 使用 `--overlay`；
   原目标为托管镜像的脚本需改为维护上游或选择本地覆盖层。

不提供一条自动复制所有秘密文件的备份命令；备份位置和恢复由用户现有流程管理。

### 8.3 升级后核对与人工调整

1. 在全局上下文以及每个重要项目目录分别运行 `env list`、`env explain KEY` 核对来源。
   每个项目都使用其自身配置解析出的 overlay，不能用一个项目的结果代表全部项目。
   `explain` 只说明当前上下文，不扫描其他项目，也不计算旧版结果。
2. 若本机或项目需要覆盖共享基线，保留相应显式项，按明确目标命令维护。
3. 若希望继承 overlay 或新版内置值，人工核对后删除对应层的显式项，再检查新来源。
   不能只凭“等于默认值”决定删除，也不能只删除一个层就假定已恢复到 overlay。
4. 原本依赖 overlay 压过本机旧值的用户，应删除不再需要的本地同键项；
   需要强制团队策略的场景不在本功能范围内，普通 overlay 不再提供该保证。
5. 核对 `KEY_SECRET` 的来源；删除 plaintext `KEY` 或修改其优先级不会取消密文键优先。
6. 完成配置核对后，使用既有 `shine update` 检查安装产物，并审查 `shine upgrade` 的 Plan 后更新。
   修改配置或升级二进制本身不构成预设执行授权。

拟议的人工调整示例：

```bash
shine env explain HTTP_PROXY_PORT
# 已确认该显式项不再需要：只删除指定层，不影响其他层。
shine env delete HTTP_PROXY_PORT --global
shine env explain HTTP_PROXY_PORT
```

历史默认值不会自动消失：保留下来的项仍会覆盖 overlay，且不会自动跟随新版默认值变化。
如果用户选择不清理，这是有效且受支持的显式配置状态。

### 8.4 人工回退

回退二进制会恢复旧排序，可能再次改变当前有效值。
按需恢复自己备份的配置，先核对期间的新编辑，避免整文件覆盖丢失无关变更。
仅回退二进制不能撤销手工删除或已应用的安装产物更新；产物须通过既有 lifecycle 再次审查处理。
新版没有附加策略标记或配置格式转换需要撤销，也不提供专用自动恢复入口。

## 9. 安全与架构约束

- 沿用私有原子写入、注释保留和项目稀疏持久化，不让有效值泄漏到错误层。
- 所有写入只触及用户选择的文件；拒绝不受支持的文件类型和符号链接目标，不越过 ownership 检查。
- 项目和预设不能生成信任 grant，来源说明不能取代 snapshot-bound Plan 审批。
- 修改 env 后，后续 lifecycle 必须重新绑定有效输入与配置 revision，不能复用旧批准。
- 来源检查不执行 generators、hooks、加密解密工具或外部脚本。
- 此处面向本地终端的路径与来源诊断不能直接扩展到现有脱敏的 Frontend/Plan DTO。
- Git 托管镜像保持可丢弃特性；本 PRD 不改变 pull 的同步实现。

## 10. 交付顺序与文档

1. 建立原始层、有效值、来源与定向写入模型；先验证不误保存继承值。
2. 停止默认值补写，统一读取顺序，补全来源展示和明确目标接口、并发检查及旧参数错误提示。
3. 完成平台验证、升级与回退演练，以 breaking release 发布；不提前在稳定版部分启用新规则。
   按仓库 SemVer 约定使用 major 变更，具体版本号依据最新稳定标签决定，本次不修改版本。

实现时更新英文与简体中文手册的配置参考、env 指南、人工升级说明和 CLI 示例，
同时更新 KB 配置数据流、不变量及新增 ADR，记录历史 overlay 优先与写入保护语义的替代。
CHANGELOG 手写并明确不兼容项。公开手册应提供用户所需的人工升级步骤，
本文及内部架构与发布流程不得通过公共站点发布。
