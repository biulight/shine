# 0016 — Generated app files and Surge URI subscriptions

- **Status**: accepted
- **Evidence**: `cli/src/apps/generator.rs`,
  `presets/app/surge/generate-subscription.ts`,
  `presets/app/surge/shine.toml`
- **Supersedes**: ADR 0009's narrower conclusion that Shine never fetches a
  Surge subscription. Artifact build scripts remain explicit-only.

## Context

The Surge preset originally treated every installed file as static preset
content and left subscription refresh entirely to Surge. A provider now exposes
a Base64 list of `ss://`, `vmess://`, and `vless://` records rather than a Surge
profile. Surge cannot consume that wire format directly, and lifecycle hooks
cannot solve the problem: hooks run only after another file changes, while
`shine update` must detect remote changes without writing.

Writing downloaded nodes into user-maintained `local-proxies.conf` would also
break ownership. The manifest would correctly classify the out-of-band rewrite
as a user modification and refuse a later upgrade.

## Decision

Add an optional generator to an app `[[files]]` entry. Its static `source`
remains the fallback and manifest identity. When `when_env` is configured, the
generator runs with only the explicitly declared config env values plus the
fixed `SHINE_APP_*` paths. UTF-8 stdout is passed through the existing
transform, desired-hash, install, and manifest pipeline.

- Install and upgrade may apply generated bytes; update only materializes and
  compares them in memory.
- External preset or overlay generators require `allow_app_hooks = true`.
- Execution has a deadline and bounded accepted stdout/stderr.
- Failure retains an existing managed destination. With no successful installed
  snapshot, an enabled generator failure is fatal.
- Generator failures and summaries must redact URLs, credentials, UUIDs, and
  raw records.

The built-in Surge generator uses Bun to download an HTTPS Base64 URI list. It
converts compatible Shadowsocks and VMess records to bare Surge policy lines.
VLESS, unsupported VMess transports, plugins, malformed records, and exact
duplicates are counted and skipped. Zero compatible nodes is a failure.

The generated file is not included in `[Proxy]`. A `Subscription` group loads
it with `policy-path=subscription-proxies.conf` and supplies `DIRECT` as a safe
fallback. Other groups may use `include-other-group=Subscription`.

## Consequences

- `shine install`, `shine update`, and `shine upgrade` all refresh the remote
  desired state while preserving update's read-only contract.
- User-owned local proxy definitions remain independent from generated nodes.
- The generator requires Bun only when `SURGE_SUBSCRIPTION_URL` enables it.
  Separately, ADR 0017's explicit Surge build/unbuild artifacts also use Bun.
- Removing the URL restores static fallback behavior; uninstall continues to be
  driven solely by the app manifest.
- Artifact scripts and teardown semantics from ADRs 0009/0012 are unchanged.
